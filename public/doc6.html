1Para.js nedir?

Para.js, Parax'ın arka plan hata günlüğüdür: uygulamada bir hata olduğunda onu sessizce yakalayıp ekibe ileten görünmez katmandır. Sen hiçbir şey görmezsin; ama o an, hatanın fotoğrafı çoktan çekilmiştir.

Teknik olarak sıfır ayarlı bir gözetmendir: sayfa açılır açılmaz Para.init() ile başlar, tarayıcının üç hata kanalını dinler — yakalanmamış hatalar (onerror), tutulmamış söz (promise) reddedilmeleri (unhandledrejection) ve konsol hata çıktıları (console.error). Hiçbiri kullanıcıyı rahatsız etmez.

Günlük hayattan benzetme: Oddiss sana "ne oldu, ne yap" diyen resepsiyonistse, para.js arka odada kayıt tutan memurdur.

2Neden yapıldı?

  • Sessiz ölümler: Birçok hata kullanıcının ekranında iz bırakmaz; sayfa donar, mesaj gitmez, kimse nedenini bilmez. Yakalanmayan hata, düzeltilmeyen hatadır.
  • "Bende çalışıyor" sorunu: Geliştiricinin cihazında görünmeyen hata, binlerce farklı tarayıcıda patlar. Gerçek cihazlardan gelen gerçek kayıtlar olmadan hata avı kör dövüşüdür.
  • Oddiss'in diğer yarısı: Oddiss kullanıcıya kodu gösterir; para.js aynı olayın teknik kaydını ekibe ulaştırır. Destek "91 aldım" dediğinde ekip kaydı bulur — eşleşme bu sayede olur.

3Nasıl çalışır?

  1. Yakala: Hata üç kanaldan birine düşer; para.js anında yakalar.
  2. Paketle: Hata mesajı, yığın izi (stack), sayfa adresi, tarayıcı bilgisi, kullanıcı kimliği ve bir parmak izi (aynı hataları gruplamak için) tek kayda konur.
  3. Kuyrukla: Firebase henüz hazır değilse kayıt bekletilir; hazır olunca topluca gönderilir. Hiçbir hata "erken oldu" diye kaybolmaz.
  4. Çift yaz: Kayıt hem Firestore errors koleksiyonuna hem de /api/log hattına yazılır; biri aksasa diğeri taşır.
  5. Ekip görür: Kayıtlar hata panelinde toplanır; aynı parmak izli hatalar tek grupta birleşir.

Kullanıcı giriş yaptığında kayıtlar o kullanıcıya bağlanır; çıkışıkken gelen hatalar anonim sayılır. Her iki durumda da içerik aynıdır, yalnızca kimlik alanı değişir.

4Ekmek kırıntıları (breadcrumbs) nedir?

Hata tek başına "ne oldu?" der ama "oraya nasıl gelindi?" demez. para-addon bu boşluğu doldurur: hatadan önceki son 20 olayı (tıklamalar, sayfa geçişleri, başarısız ağ istekleri) ekmek kırıntısı gibi toplar ve hata kaydına ekler.

Örnek: "mesaj gönderilemedi" hatasının kırıntıları "kanal seçildi → yazıldı → gönder basıldı → ağ isteği başarısız" diyorsa, ekip sorunun düğmede değil ağ katmanında olduğunu anında bilir. Kırıntılar 20'yi aşınca en eskisi silinir; liste hep taze kalır.

5Ne toplar, ne toplamaz?

Durum
Hata mesajı + yığın iziToplanır (teknik teşhis için)
Sayfa adresi, tarayıcı bilgisiToplanır (hangi ortamda olduğunu bulmak için)
Kullanıcı kimliğiGirişliyse toplanır (kaydı hesaba bağlamak için)
Tıklama/geçiş kırıntıları (son 20)Toplanır (olay öncesi bağlam için)
Şifreler, mesaj içerikleriAsla toplanmaz
Kamera, mikrofon, konumErişilmez, toplanmaz

Kayıtları yalnızca sahibi okuyabilir (Firestore kuralı); güncelleme ve silme tamamen kapalıdır — kayıtlar delil gibi korunur.

Şifreni bir hata mesajının içine yazdıysan (örn. konsola yapıştırdıysan) o metin kayda girebilir. Şifrelerini asla hata kutularına, konsola veya sohbete yazma.

6Geliştiriciler için: elle kayıt

Otomatik yakalamanın görmediği yerlerde (örn. yakalanan ama önemli bir hata) kayıt elle bırakılır:

Para.capture(new Error("Oda kodu üretilemedi"), {
  type: "custom",
  context: "odaAc"
});

type hatanın türünü, context hangi işte olduğunu söyler; kırıntılar otomatik eklenir. Bot ve eklenti geliştiricileri aynı deseni kullanabilir.

7Sık sorulan sorular

  • Beni izliyor mu? Hayır. Davranışını değil, uygulamanın hatalarını kaydeder. Ne tıkladığının listesi tutulmaz; yalnızca hata öncesi son 20 teknik olay.
  • İnternetimi yavaşlatır mı? Hayır. Kayıtlar küçük ve arka planda gönderilir; sohbet akışını etkilemez.
  • Kapatabilir miyim? Parçası olduğu uygulamadan ayrı bir düğmesi yoktur; kişisel veri toplamadığı için kapatmaya gerek de yoktur.
  • Kayıtlarım silinir mi? Hata kayıtları teşhis amaçlı saklanır; hesabını silmen durumunda kimlik bağın kopar.
  • Oddiss kodumla bağlantısı ne? Gördüğün kodun teknik karşılığı para.js kaydında durur. Destek ekibi kodunla kaydı eşleştirir.

1What is para.js?

Para.js is Parax's background error logger: the invisible layer that silently catches an error in the app and reports it to the team. You see nothing; but by then, the error's photograph is already taken.

Technically it is a zero-config watcher: it starts with Para.init() the moment the page opens and listens to the browser's three error channels — uncaught errors (onerror), unhandled promise rejections (unhandledrejection), and console error output (console.error). None of them disturb the user.

An everyday analogy: if Oddiss is the receptionist telling you "what happened, what to do", para.js is the clerk filing records in the back room.

2Why was it built?

  • Silent deaths: Many errors leave no trace on the user's screen; the page freezes, the message never sends, nobody knows why. An uncaught error is an unfixed error.
  • The "works on my machine" problem: A bug invisible on the developer's device explodes across thousands of different browsers. Hunting bugs without real records from real devices is a blind fight.
  • Oddiss's other half: Oddiss shows the user the code; para.js delivers the technical record of the same event to the team. When support hears "I got 91", the team finds the record — the match happens this way.

3How does it work?

  1. Capture: The error lands in one of the three channels; para.js catches it instantly.
  2. Package: Error message, stack trace, page URL, browser info, user identity, and a fingerprint (to group identical errors) go into one record.
  3. Queue: If Firebase isn't ready yet, records wait; once ready, they're flushed together. No error is ever lost for being "too early".
  4. Dual write: The record goes both to the Firestore errors collection and the /api/log pipeline; if one fails, the other carries it.
  5. Team sees: Records gather in the error panel; errors with the same fingerprint merge into one group.

When you're logged in, records attach to your user; errors while logged out count as anonymous. The content is identical either way — only the identity field changes.

4What are breadcrumbs?

An error alone says "what happened" but not "how did we get here". para-addon fills that gap: it collects the last 20 events before the error (clicks, page navigations, failed network requests) like breadcrumbs and attaches them to the record.

Example: if the breadcrumbs of a "message failed to send" error read "channel selected → typed → send pressed → network request failed", the team instantly knows the problem is in the network layer, not the button. Past 20, the oldest crumb is dropped; the list stays fresh.

5What does it collect — and not?

Status
Error message + stack traceCollected (for technical diagnosis)
Page URL, browser infoCollected (to find the environment)
User identityCollected if logged in (to attach the record)
Click/navigation crumbs (last 20)Collected (for pre-event context)
Passwords, message contentsNever collected
Camera, microphone, locationNever accessed or collected

Records are readable only by their owner (Firestore rule); update and delete are fully closed — records are preserved like evidence.

If you typed your password into an error message (e.g. pasted it into the console), that text can end up in a record. Never type passwords into error boxes, the console, or chat.

6For developers: manual capture

Where automatic capture can't see (e.g. a caught but important error), a record is left manually:

Para.capture(new Error("Room code could not be generated"), {
  type: "custom",
  context: "odaAc"
});

type says the kind of error, context says which job it happened in; breadcrumbs attach automatically. Bot and extension developers can use the same pattern.

7FAQ

  • Is it watching me? No. It records the app's errors, not your behavior. No list of what you clicked is kept; only the last 20 technical events before an error.
  • Does it slow my internet? No. Records are tiny and sent in the background; chat flow is unaffected.
  • Can I turn it off? It has no separate switch from the app it belongs to; since it collects no personal data, there is no need to.
  • Are my records deleted? Error records are kept for diagnosis; if you delete your account, the identity link is cut.
  • How does it relate to my Oddiss code? The technical counterpart of the code you see sits in the para.js record. Support matches your code to the record.
